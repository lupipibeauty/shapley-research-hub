# 03 表示增长分析

## 状态数与来源式大小不是同一参数

六个 E1 游戏提供了直接反例：concentrated/dispersed 的联合统计状态分别为 16/49，但二者的 GC DNF、Harsanyi 项数、primal graph 与 ADD 节点数完全相同。统计状态计数度量 `Q(S)` 的不同数值结果；来源式大小度量哪些玩家组合激活阈值事件。二者可能相关，但不存在单调等价关系。

上一阶段五个冻结游戏则从另一侧说明问题：它们均只有 16 个六维状态，但 G2 Harsanyi 项分别为 8、48、44、72、56。相同状态数仍可对应不同证明重叠和布尔展开规模。证据来自冻结运行 `../IDEA03_2_joint_value_deepening_v1/runs/DEEP_20261113_155744/raw/component_metrics.csv`。

## 为什么集中证明有时更小

若多条证明共享同一前缀变量集，知识编译器可以把公共合取提取一次；若集中还使多个阈值分量具有完全相同的激活条件，跨分量缓存也能复用。相反，分散证明若引入不同变量组合，会增加唯一子句与 frontier 宽度。

但集中也可能更难：大量证明共享部分而非全部变量时，会形成高连接度 primal graph；变量顺序不合适时，中间 frontier 反而增大。是否增减必须由“唯一子表达式、图宽、变量顺序、条件化后的剩余函数数”共同判断，不能由 concentrated 标签判断。

## 本轮直接结果

E1 两种模式均有 108 条 GC 原始子句、63 条唯一子句、45 次可复用子句出现、392 个 Harsanyi 项和最高阶 16。换言之，本轮城市重分布在省级 GC 上被 OR 语义消去了，既没有增加也没有减少表示。

首次实现直接对 18 条 DNF 子句做 `2^18` 包含—排除并在多分量上重复，导致 `RESOURCE_LIMIT`。改用 N≤16 真值表上的 O(N·2^N) Möbius 变换后，六个游戏均完成。这一失败说明“转换算法”本身可制造瓶颈；它不是游戏固有复杂度证据。

## 可检验的下一参数

下一阶段应冻结状态数和总见证数，分别改变：跨省共享玩家数、唯一证明子句数、primal treewidth、同一阈值的替代证明数。只有这些参数变化时成熟编译器节点数也系统变化，才可提出表示增长规律。
