# RQ3 成本交互报告

## 1. 适用范围

本轮只有 H3-S6 evidence-state 方法同时具备“非全联盟枚举”和“小规模同目标 oracle 核验”资格。E1 每个独立 fixture 只计时一次，因此以下结果是机制筛查，不是正式性能推断；不得把三个 seed 当作计时重复，也不报告显著性检验。

## 2. N=20 跨地区联合四格交互

H3-S6 的跨地区 `total_cold_seconds` 交互为：

| fixture | Delta_T（秒） | K_T | log K_T |
|---|---:|---:|---:|
| S9201 | 1.061 | 1.146 | 0.136 |
| S9202 | -0.952 | 0.883 | -0.124 |
| S9203 | 1.138 | 1.139 | 0.130 |

中位数为 Delta_T=1.061 秒、K_T=1.139，但三组方向不一致。分阶段中位数为：

- compile：Delta_T=-0.0048 秒，K_T=0.996。
- solve：Delta_T=1.066 秒，K_T=1.165。
- cold total：Delta_T=1.061 秒，K_T=1.139。

这些单次计时不足以排除调度、缓存和 Python 运行时波动。现阶段只能说“两个实例出现正交互，一个实例出现负交互”，不能说额外成本已经稳定存在。

## 3. 同地区对照

local 的 cold-total 交互在三个 fixture 中均为负：-0.874、-0.501、-0.700 秒，对应 K_T 为0.910、0.941、0.914。它提示普通指标非可加性本身没有在当前实现中形成正的额外成本，但同样受单次计时限制。

## 4. 结构指标解释

N=20 的 Low/High 最大 frontier 均为38,416；累计 cached factor states 分别为129,354和130,302，高共享只增加约0.73%。同一结构下 add/joint 使用相同 evidence-state 图，价值形式主要影响 terminal value 计算和反向求值，而不改变结构 frontier。

因此当前正负波动没有对应到稳定的编译宽度变化。不能仅因 D 单元偶尔更慢就判定 RQ3 成立。

## 5. 反证：分别编译与共享编译

在 S9201 High/cross-add 上：

- 直接在同一 evidence-state 图计算可加目标：7.445 秒。
- 两个坐标分别编译并按线性合并：16.557 秒。
- 两者均通过 oracle，分别编译误差为 `5.258e-13`。

这个单实例结果说明成熟的共享来源表达能够避免重复编译；它不是对所有方法或规模的普遍结论。

## 6. N=24 资源门

修正后的 E2 没有枚举玩家联盟。Low/High 和四个价值均在 S6 编译层出现同一失败：`AD layer 414736 exceeds cap 300000`，峰值 RSS 约186–188 MB，solve 阶段未执行。

失败与 add/joint、local/cross、Low/High 无关，故它反映的是当前 evidence-state 表示随 witness 数增长的结构状态爆炸，而不是“共同来源 × 联合价值”的已识别额外交互。按停止条件，未运行其余5个 seed、N=32、N=40、N=64。

## 7. 当前结论

在 N=20，跨地区共同来源与联合价值的额外成本方向不稳定；在 N=24，当前合格基线被一般结构状态上限阻塞，且阻塞不区分四格。RQ3 的正命题尚未获得支持。
