# 证据缺口与待核实清单

## 优先级说明

- P0：直接影响现有论文结论、实验身份或可复现性。
- P1：影响比较公平性和研究历史完整性。
- P2：有助于维护，但不改变当前主要判断。

## P0：优先核实

| 缺口 | 当前证据 | 需要补充的材料 | 影响 |
|---|---|---|---|
| 工作区无 Git 元数据 | 根目录及子目录均未发现 `.git` | 原仓库地址、bundle、`.git` 备份或提交导出 | 无法恢复分支、提交、worktree、tracked/untracked 和提交编号 |
| GNN 玩家—事实绑定清单缺失 | 生成器和数据文件存在 | 每个代表游戏的 player_id→物理表/主键列表及生成规则版本 | 第三章玩家定义与第五章数据构造不能逐例对齐 |
| GNN 消息方向与理论描述不一致风险 | 源码显示正向边；公式按进入邻居聚合 | 实际 edge_index 类型、是否在加载时加反向边、一次前向传播 trace | 影响“玩家学习下游来源关系”的核心机理表述 |
| 精确标签生命周期未完全串联 | 数据、校验和训练结果存在 | 数据生成命令、代码版本、随机种子、输入摘要、输出哈希 | 无法证明 checkpoint 对应哪一版精确标签 |
| M1/M2 原始结果不完整 | 有报告/历史索引 | 原代码、配置、日志、结果表 | 相关早期结论目前只能给 B/C 级，不能升级为 A |
| P3-1C 子版本参数映射不清 | 结果目录和历史名称存在 | R1/R2/C2 的 manifest 对照表 | 无法严谨解释版本间唯一改变因素 |

## P1：比较与失败归因

| 缺口 | 当前证据 | 需要补充的材料 | 影响 |
|---|---|---|---|
| LexaShap 91 个失败未分类 | 成功/失败计数和日志存在 | 按错误类型、输入特征、资源状态分类 | 不能判断是算法覆盖边界还是工程问题 |
| Abramovich Figure 4 口径不一致 | 局部汇总存在 | 论文筛选规则、硬件、超时、重复次数 | 不能称严格复现 |
| Luo SF1/no-vertical 资源信息不全 | 内存错误和阶段信息存在 | 峰值 RSS、内存上限、中间基数、原 Ubuntu 对照 | 不能归因于算法还是环境 |
| Luo IUSV 停止准则缺失 | 明确为用户暂停 | 原定预算、checkpoint、恢复策略 | 部分时间不能进入完整性能曲线 |
| H5-SCALE 跳过/真值边界 | 规模实验材料存在 | 每个规模的 oracle 可用性、跳过理由、资源上限 | 规模结论可能混合算法和资源筛选 |
| GNN 基线计时口径 | 端到端表存在 | 冷/热缓存、并发、硬件、预处理、训练/标签成本边界 | 约 1/95 仅能按当前测量定义解释 |
| MSR 文献实现一致性 | 本地实现结果存在 | 公式、超参数、采样预算与原文逐项对照 | 目前只能否定“当前实现”，不能否定方法族 |
| GNN 外部零样本仅四个游戏 | 完整结果存在 | 更多独立来源模式或预注册迁移集合 | 目前足以否定强主张，不足以刻画迁移边界 |

## P2：档案可维护性

| 缺口 | 建议材料 |
|---|---|
| 多处 handoff/compact/zip 解包目录内容重复 | 只读重复清单、来源标识和首选入口；本轮不移动或删除 |
| 图表与生成脚本对应关系不统一 | `figure_manifest.csv`：图号、输入、脚本、配置、输出 |
| 报告引用路径可能使用旧绝对路径 | 路径重定位清单，不改原报告 |
| 硬件与软件环境记录分散 | 每个正式 run 的 `environment.json` |
| 早期实验提出原因缺失 | 原笔记、issue 导出、聊天交接；找不到则永久标记“动机待核实” |
| Excel/Word/PDF 与 Markdown 版本关系不清 | 文档版本索引、生成来源、日期和是否权威 |

## 发现的口径冲突或易误读事项

1. “目录中有脚本”不等于“实验已运行”；ProvSQL 和 M3 属于典型情况。
2. “报告声称完成”不自动是 A 级；A 需要代码、配置和结果可对应。
3. IUSV 是用户暂停，不应改写为超时。
4. SF1 RDSV 是当前环境内存失败，不是算法理论否定。
5. P1 manifest 明确是 `P1_COMPLETED_P2_NOT_RUN`；后来 P2 有独立执行证据，但不能据此改写 P1 当时状态。
6. GNN Softmax/遮罩只支持相应约束，不支持完整 Shapley 公理声明。
7. 外部零样本失败与 SF1 同来源模式的规模外推成功是不同分布外问题，不能互相替代。

## 建议首先寻找的原始材料

1. 原 Git 仓库或 `.git` 备份。
2. GNN 游戏生成器输出的玩家—事实映射及反向边配置证据。
3. P3-1C R1/R2/C2 manifest。
4. LexaShap 91 个失败的逐例日志索引。
5. Luo 原 Ubuntu 环境记录与峰值内存数据。
6. M1/M2 原始运行目录和 M3 是否曾在其他位置执行的证明。
