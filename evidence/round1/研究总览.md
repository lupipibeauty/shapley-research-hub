## 一、先说结论

当前工作区不是一个可由 Git 统一解释的仓库：在根目录执行 Git 根目录、分支、日志和 Worktree 检查均返回“not a git repository”，递归检查也未发现可用的 `.git` 工作树。因此，本轮无法给任何实验附上提交编号，也无法可靠区分“已跟踪”和“未跟踪”文件。现有历史主要由文件时间、manifest、运行配置、原始 CSV/JSON、日志及交接文档恢复。

本轮共索引 **62 个实验或复现任务**：旧台账中的 43 项全部找到了其登记路径；另补入旧台账遗漏的 P1、H3-J2、Luo 消融等 5 项，以及 14 个 GNN 正式实验族。调试型 smoke 重跑、重复绘图版本和交接压缩包没有重复计为独立实验。

整个工作区实际包含三条相互关联但目标不同的研究线：

1. **精确记录级 Shapley 与数据库结构研究**：从旧 D1、D1-P、AB/H3/H5 到 P2/P3，研究固定玩家和价值函数下，SQL 来源、统计状态、知识编译及全玩家求解的正确性和成本。

3. **GNN 摊销近似研究**：在 TPC-H 派生游戏上训练 RPV-GNN，比较 MLP、Monte Carlo、回归控制变量、消融、扰动、外部零样本和端到端成本。该方向不是精确算法线的直接替代，而是面向重复贡献估算的近似推理路线。

## 三、研究进展概况

### 1. 已完成并有较强证据的内容

- D1-P 的 12 个逻辑记录包、35 个坐标及 4096 个联盟已经完成 SQL、共享状态、价值函数和精确 Shapley 的一致性核验。
- AB-N1/N2/N3-L、AB-J1/J2 证明若干单层、多层、JOIN、DISTINCT 和 HAVING 受控实例可以由现有来源编译或经典精确方法处理。
- AB-N4-DP 否定了“V1 比例评分必须枚举全部联盟”的直觉；低维计数状态已经给出精确解。
- H5/H5-SCALE/H5-R 已记录联合价值状态、共享程度、预处理和全玩家共享求解的成本边界，但大规模部分不能外推为复杂度定理。
- P2 的来源×层次×价值受控实验、P3-0 的 13 玩家精确锚点、P3-1B/1C 的门槛分解及 Abramovich 同目标适配均有代码、配置、结果和日志。
- GNN 主实验包含三个训练种子、三个测试场景、图边和锚点消融、MC 与 MSR 基线、哑玩家、扰动、外部零样本和端到端 DuckDB 成本。其正式冻结结果可由 `RESULTS_FINAL_EXPERIMENTS.md` 与对应 run 目录交叉核验。

### 2. 已完成但结论必须受限

- Abramovich Academic 正式批次只覆盖发布包中已有 DNF 输入，不含 SQL/ProvSQL 来源生成；LExaShap 有 91 个未成功实例。
- Luo SF0.1 RDSV 是 Windows 兼容缩小运行，不是论文 SF1 原规模复现；SF1 在 JOIN 阶段因内存失败。
- P3 和 H3-J2 的同目标适配只覆盖可加子游戏或 DISTINCT-DNF 后端，不能声称已覆盖 D1-P V1/V2 完整价值。
- GNN 的同模式和 SF1 规模外推有结果，但四个 D1-P/P3 外部游戏没有形成稳定的跨模式优势。
- GNN 端到端成本不包括训练标签生成和模型训练，只能支持“训练完成后的摊销推理潜力”。

### 3. 已停止、失败或被现有方法覆盖

- M3 只有设计方案，没有 BDD、变量顺序或性能运行，状态为 D。
- ProvSQL 只有环境／接口检查，没有正式可比运行，状态为 E。
- Luo SF1 RDSV 因本机内存阻塞；no-vertical 消融也出现可复核内存失败，状态为 E。
- “多表 JOIN 自然产生新的 Shapley 难题”“non-hierarchical 标签自动导致困难”“V1 必须全联盟枚举”“减少逐玩家重复一定降低端到端时间”等直觉均已被实验否定或降级。
- RAPID-GAP 的两个静态候选被经典 VE、计数 DP 或生成函数覆盖，当前静态新算法主张状态为 F。
- GNN 的 MSR 控制变量适配未优于普通缓存置换 MC；这只否定当前适配，不否定所有文献 MSR。

## 四、当前可继续但尚未完成的研究问题

1. **精确算法主线候选**：固定玩家、SQL 和价值定义，检验“共享 SQL witness × 非可加联合价值”的 2×2 受控设计是否产生不能被现有 VE/MTBDD/d-DNNF 直接消除的端到端重复成本。该实验目前仍是方案，未执行。
2. **多指标共享来源编译**：比较逐指标 lineage/编译与一次共享电路的完整端到端成本，并记录中间节点、峰值内存和变量顺序；当前缺 ProvSQL 或等价公开管线。
3. **GNN 适用边界修订**：现有模型只沿玩家→见证→坐标→价值因子→报表的正向边传播，玩家局部表示不能接收下游见证信息；结构信息主要经共享图级池化进入贡献头。若不重训双向图，理论部分必须保持这一受限表述。
4. **玩家—事实绑定复现材料**：D1-P 与外部适配仍需导出游戏生成器的“游戏—玩家—物理事实”映射清单，才能让问题定义、数据构造和实际联盟操作完全对应。
