# Codex 科研工作规程（草案，新基线建立后适用）

## 工作前
1. 阅读 `RESEARCH_STATUS.md`，再阅读指定 Idea 和相关历史实验索引及第二轮核验事实；禁止每次无目的地遍历整个项目。
2. 明确本次任务的研究问题、玩家身份、联盟/查询/价值、变化因素、固定条件、比较基线和停止条件。
3. 区分讨论计划、仅编码、实际执行、作者复现、同目标适配、环境阻塞及命题被否定。
4. 若任务涉及旧历史，用旧路径/manifest/hash 证明；没有旧 Git 提交时不得虚构。

## 执行时
5. 一个短期实验分支对应一个子 Issue，尽量只变更一项预先说明的因素；不创建所谓长期 Idea 代码分支。
6. 原始冻结数据、历史报告和旧实验目录保持不变。新任务不得在未经批准时自动进行代码重构、框架搭建或扩大规模。
7. 实验输出应进入 `runs/<experiment_id>/<run_id>/`，保留 manifest、配置快照、环境、输入标识和 SHA-256、stdout/stderr、指标与结果。
8. 失败、用户暂停、预算终止和内存不足应分别归档，不能只保留成功样本。
9. 不能只比较训练完成后的推理成本而声称总成本更低；必须标明训练标签、训练、输入构造等计时边界。
10. 若同一数据支持多个 Idea，只通过唯一 run ID/证据链接引用，不重复复制大数据。

## 交付时
11. 同步更新 run 证据、实验索引、Idea 状态与 `RESEARCH_STATUS.md`，并在 PR 中说明结论适用范围。
12. 先给证据和可复核的结论，再提出下一步实验；未经批准不启动下一次探索。
13. 不能将结构观测上更快或报告更好的数值，自动包装为算法创新或经济价值依据。
14. 不执行 GitHub 发布、仓库初始化、文件移动、删除或大规模提交，除非用户明确同意具体变更范围。
