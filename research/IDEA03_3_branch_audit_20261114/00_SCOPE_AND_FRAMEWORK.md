# IDEA-03-3 分支级文献与理论覆盖审计：范围与判别框架

## 1. 本轮边界

本轮只审计文献、理论边界、作者实现和既有实验；未运行新的 Shapley 实验，未修改历史代码、数据或 canonical run，也未创建 Git 提交。

研究对象固定为完整多层级、多指标统计产品：

\[
Y(S)=Q(D_S)=\{y_{g,f}(S)\}_{g\in\mathcal G,f\in\mathcal F},
\qquad V(S)=G(Y(S)),
\]

玩家是参与联盟的底层物理事实，维表等外生关系固定。目标输出包括单个价值函数的玩家 Shapley 向量，也包括坐标级归因矩阵

\[
\Phi=[\phi_i(y_m)]_{m=1,\ldots,M;i=1,\ldots,N}
\]

以及同一报表上多个价值函数 \(G_1,\ldots,G_K\) 的归因结果。

## 2. 五层共享框架

| 层 | 共享对象 | 本题中的意义 | 是否能单独回答主问题 |
|---|---|---|---|
| L1 SQL 执行 | 扫描、连接、分组 | 降低报表生成成本 | 否 |
| L2 provenance 构造 | witness、表达式、公共子式 | 避免重复生成来源 | 否 |
| L3 表示 | d-tree、d-DNNF、OBDD、算术 DAG、view tree | 压缩同一来源结构 | 否 |
| L4 数值聚合状态 | COUNT、COUNT DISTINCT、SUM、比例、NULL 等共同状态 | 直接决定能否避免逐坐标重复求值 | 是 |
| L5 Shapley/归因 | coalition-size 消息、反向传播、全玩家/多根归因 | 直接决定能否避免逐输出重复归因 | 是 |

因此，“共享扫描”“共享 provenance DAG”或“多输出 aggregate engine”只能证明 L1--L4 的某些部分成熟，不能自动推出 L5 的完整报表 Shapley 已解决。

## 3. 覆盖状态

每个分支只使用以下状态之一：

- `DIRECTLY_COVERED`：同一玩家、同一类价值对象、同一输出目标已有直接算法。
- `REDUCTION_COVERED`：可通过有证明的精确归约交给成熟算法。
- `ENGINEERING_ONLY`：理论对象已覆盖，仅剩实现整合或常数优化。
- `REPRESENTATION_ONLY`：只覆盖表达/编译，未覆盖目标归因。
- `UNCLEAR_NEEDS_ONE_GATE`：理论与实现证据不足，只允许一个判别性 gate。
- `SURVIVES_AUDIT`：最强相邻工作仍未直接或经精确归约覆盖。

## 4. 输出规模基线

- 单个价值函数、全部玩家：至少写出 \(N\) 个数。
- \(M\) 个报表输出、全部玩家：若要求显式矩阵，至少写出 \(MN\) 个数。
- \(K\) 个价值函数、全部玩家：至少写出 \(KN\) 个数。

因此，本审计不把不可避免的结果写出成本称为算法低效；只审查输出之前是否存在可共享的中间计算。

## 5. 证据规则

1. 报告结论必须回到原始代码、CSV/JSON、日志或论文正文。
2. 摘要只用于发现文献；没有正文定位的结论标记为 `ABSTRACT_ONLY_NOT_ENOUGH`，不用于关闭分支。
3. “术语相似”“都是图”“都有多输出”均不等于同一研究问题。
4. 数值稳定性异常已归类为 `LOCAL_IMPLEMENTATION_CHOICE_ONLY`，不再作为 IDEA-03-3 分支。
5. 页面编号统一使用 PDF 页；若论文印刷页码不同，在条目中另行注明。

## 6. 生成式 AI 披露

本轮由 Codex 辅助检索、整理和对照；最终状态基于列出的本地原始证据与论文原文定位，不以模型记忆或摘要替代原文。
