# 原文证据之后的 IDEA-03 映射

## 使用方法

本文件是最后一层。前面的原文问题、作者局限和定理边界不因本项目需要而改写。这里仅说明现有 R1--R12 可以从哪些原文边界继续发问。

| IDEA-03 候选 | 原文已经较成熟的部分 | 仍可追问的连接问题 | 最大误判风险 |
|---|---|---|---|
| R1 表示冗余与真实互补 | Blackwell/Signals 的信息比较；query pricing 的线性推导；provenance 等价 | 决策等价、查询可恢复和 `G∘Q` 等价是否能统一 | 退化为去重预处理后套标准 Shapley |
| R2 多任务精确复用 | LMFAO/F-IVM 多查询共享；Yang 的任务矩阵；FastSHAP 摊销 | 固定 Q 下哪些结构化 G 共享精确中间量 | 任意 G 无法压缩，或只重复成熟多查询技术 |
| R3 决策诱导互补 | SPO/DFL/信息价值已解释任务依赖；MC-net 可表达局部交互 | 决策模型是否限制交互阶数并与 SQL 来源结构相容 | 随意选乘积/门槛制造非加性 |
| R4 合法玩家边界 | FGSV、2D-Shapley、Owen 分别处理不同组结构 | 权利与联合交付如何诱导 record/bundle/owner game | 为加速任意打包，或把不同游戏混同 |
| R5 动态精确归因 | Xia/Yang/FedDSV、DBSP/F-IVM 已有动态方法 | 哪些更新保证联盟边际或依赖局部不变 | 把局部查询变化误认为局部 Shapley 变化 |
| R6 任务域稳健贡献 | Abbas--Hazen、Signals 研究跨任务/背景排序 | 哪些记录排序能在明确任务域内保持 | 只是对已有稳健信息排序换场景 |
| R7 SQL 到游戏的可认证编译 | provenance、MC-net、模型计数、d-tree 都有成熟表示 | `SQL + 玩家绑定 + G` 到表示的语义证书和规模界 | 只实现胶水代码，没有新理论 |
| R8 语义依赖上界与发现 | bounded dependency 已给已知依赖下算法及发现困难 | provenance 能否给不漏边候选并由 G 安全剪枝 | JOIN 邻接直接冒充语义依赖 |
| R9 两级所有权结算 | Owen/FGSV/机制设计已有多种分配概念 | 记录贡献、议价块和 owner 收益的制度一致条件 | 缺乏真实合同权利证据 |
| R10 三账本收益分配 | 信息市场区分买方、平台、来源；Dawande/Badewitz研究激励 | 买方价值、平台利润、成交后可分配池如何连接 | 把三个货币对象强行设成同一个 v(N) |
| R11 公开规则驱动多G基准 | DFL/任务价值要求行动和损失；公开规则可冻结任务 | 公共任务能否成为可审计算法基准 | 把公共评分说成商业成交价值 |
| R12 背景信息敏感区间 | Signals、incomplete games 提供邻近理论 | 背景信息未知时贡献点值是否应变成区间/偏序 | 竞争原文未补齐，过早声明新解概念 |

## 目前不应由 Codex 自动做的决定

1. 哪个连接问题最重要。
2. 是优先解释现实收入，还是优先研究精确表示。
3. 是否接受公共规则任务作为真实场景替代。
4. 玩家应由技术来源、业务交付还是所有权定义。
5. 哪个结果足以构成你愿意长期研究的“意外”。

这些判断应先由研究者根据 `05_CRITICAL_QUESTION_AND_DIVERGENCE_BANK.md` 作出。Codex 后续负责形式化、反例、竞争原文核验和最小验证设计。
