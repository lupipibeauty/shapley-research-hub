# 十张故事卡的共同理论关系

## 1. 本轮新看清的三层分解

十张卡不是十个相互独立的问题。它们围绕同一条映射链：

\[
\text{供给与控制规则}
\Rightarrow N,D_S
\Rightarrow Y(S)=Q(D_S)
\Rightarrow V_k(S)=G_k(Y(S))
\Rightarrow \phi_i(V_k)
\Rightarrow p_{ik}.
\]

文献分别在三层形成成熟理论：

1. **价值层**：Blackwell、Abbas–Hazen、Data Shapley、Coyle–Manley说明信息价值依赖决策问题、效用、背景信息和评价目的。
2. **玩家层**：FGSV、Owen、2D-Shapley、replication-robust markets说明个体、组、二维碎片、所有者与战略复制不是同一对象。
3. **计算层**：provenance semiring/semimodule、database Shapley、model counting、LExaShap、LMFAO/F-IVM说明来源表达、聚合、共享和精确归因已有广泛工具。

目前没有证据表明“把三层顺序串接”本身产生新理论。候选研究必须在层与层之间找到一个不可删除的约束。

## 2. 四个跨卡共同问题

### 2.1 任务价值与玩家粒度

改变 `G` 会改变 record、bundle 和 owner 游戏的边际，但这只是一般事实。较强问题是：真实可控制/交付单位是否在某类任务互补下产生可证明的一致或不一致条件。C1+ A1 可发展，但必须补 Owen 原文。

### 2.2 表示冗余与分配不变性

A2 的核心不是层次数量，而是 `Y` 的可恢复变换是否保持决策相关信息。若逐联盟 characteristic function 相同，Shapley 自然相同；困难在于报表同时包含可恢复和不可恢复统计，并可能有检索便利价值。A2+A3 提供“对冗余不敏感、对互补敏感”的真实张力。

### 2.3 非可加价值与来源交互

应把两种二阶差分分开：SQL/lineage 产生的事实互补，和 `G` 在报表坐标上的互补。仅看到乘积或门槛不能证明新计算困难。A3+D1 的门槛是：现有 MC-net、Boolean 分解、d-DNNF 和 aggregate-CQ 方法不能在相同 `N,Q,G` 下直接归约。

### 2.4 多任务与计算复用

B1/B2/D1 的共同对象是固定 `Y(S)` 下的任务族 `{G_k}`。D-Shap 已覆盖 ML player-by-task 维护，但多依赖相似性和局部近似。关系数据库中的精确复用空间取决于是否存在比完整联盟真值表更小、又足以回答任务族的联合状态。

## 3. 逻辑冲突

- A2 希望对表示复制不变；若报表层次本身提供易读/合规便利，A2 又允许价值改变。两者必须通过 `G` 明确区分。
- C1 不能同时把物理记录视为原子玩家，又把 owner coalition game 的结果当作同一游戏的汇总；二者是不同目标。
- D1 若只需整体标量 `G` 的 N 个份额，就不应强制生成 M×N 坐标归因矩阵；若业务需要矩阵，输出下界必须计入。
- D2 的“少量 SQL 结果变化”不等于“少量玩家 Shapley 变化”；后者涉及所有联盟边际。

## 4. 当前共同理论问题

最清晰的共同问题不是“完整报表 Shapley”，而是：

> 在真实任务定义的价值下，哪些报表变换和玩家变换保持联盟游戏或支付语义，哪些不可恢复交互必须保留；这些不变性/非不变性是否同时给出可利用的精确计算结构？

它仍是候选问题，需要 P1 文献和形式化反例继续攻击。
