## 完整中文摘要翻译

合作博弈为研究自利参与者之间的合作提供框架，并提供多种解概念来说明合作成果应如何在玩家之间分配。遗憾的是，与许多解概念有关的计算问题通常是不可解的——NP-hard 或更难。本文把 Feige 与 Izsak（2013）提出的复杂度度量——dependency degree 与 supermodular degree——引入合作博弈复杂度分析。作者证明，当博弈的 dependency degree 或 supermodular degree 有界时，许多计算问题变得可解。特别地，对 supermodular degree 较小的 simple games，多种解概念存在高效算法；计算 Shapley 值总是关于 dependency degree 的固定参数可解问题。最后，作者指出，尽管确定玩家之间的依赖关系在计算上很困难，但某些特殊博弈类存在高效算法。

## 研究问题形成

作者不满足于把博弈分为“易类/难类”：一个实例即使只轻微偏离凸性，类级算法也可能失效。于是改用参数化复杂度，寻找反映实例结构的参数（p.1063）。dependency graph 不是外部社交图，而由边际贡献是否会被另一玩家改变来定义。

## 数学对象

- TU game `(N,v)`，`v(∅)=0`（p.1064）。
- 边际贡献 `v(i|S)=v(S∪{i})-v(S)`。
- 玩家 `i` 依赖 `j`：存在不含 `i,j` 的 `S`，使加入 `j` 改变 `i` 的边际贡献。该语义关系诱导 dependency graph。
- `D(i)` 为 `i` 的依赖集合，dependency degree `d=max_i |D(i)|`。
- positive dependency/supermodular degree 只记录会严格增加边际贡献的关系；不能替代一般依赖。

## Shapley 的局部化

**Lemma 3（p.1067）**：对 `S⊆D(j)` 和 `T⊆I(j)=N\(D(j)∪{j})`，`v(j|S∪T)=v(j|S)`。证明对 `|T|` 归纳，逐个移除与 `j` 无依赖的玩家。

**Theorem 8（p.1067）**：Shapley 计算关于 dependency degree 为 FPT。把所有联盟按与 `D(i)` 的交集 `S` 和无关玩家数量 `t` 分组；同组边际由 Lemma 3 相同，只需组合计数权重。每个玩家只枚举 `2^{|D(i)|}` 个局部子集，而不是 `2^{n-1}` 个全联盟。

**Theorem 9（p.1067）**：同理，Banzhaf 值关于 dependency degree 为 FPT。

## 依赖图发现门槛

**Theorem 13（pp.1069–1070）**：仅以 characteristic-function value queries 构造 simple game 的 dependency graph，最坏至少需要 `C(n,n/2)` 次查询。证明构造一族只在特定中层联盟上有差异的 simple games，使算法必须查询大量候选才能判断某玩家是否 dummy。

因此 Theorem 8 的实际管线是“已知/可构造 `D(i)` 后求解”。若 IDEA-03 只能黑箱调用 `G(Q(D_S))`，发现语义依赖本身可能比局部 Shapley 求解更难。

## 与数据库结构的区别

至少存在三张图：

1. SQL provenance/witness 图：事实共同出现在哪些证明中；
2. 坐标来源 overlap 图：事实共同影响哪些报表坐标；
3. 对冻结游戏 `v=G∘Q` 的语义 dependency graph：一事实是否会改变另一事实的边际。

前两者可以为第3者提供候选边，但 DISTINCT、聚合抵消、NULL 规则和 `G` 可能删除或新增语义依赖。不能用 JOIN 邻接直接替代 Theorem 8 的 `D(i)`。
