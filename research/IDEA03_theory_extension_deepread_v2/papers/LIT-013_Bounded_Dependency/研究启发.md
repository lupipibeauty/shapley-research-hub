# Bounded Dependency 研究启发报告

1. **[原文明确]** Shapley 的指数枚举可按玩家的语义依赖集合局部化（Lemma 3、Theorem 8, p.1067）。值得借鉴的不是“图越稀疏越快”口号，而是边际不变性等式。
2. **[原文明确]** 从黑箱价值查询发现依赖图最坏仍需指数查询（Theorem 13, pp.1069–1070）；结构参数算法需要连同结构获取成本一起报告。
3. **[原文明确]** dependency graph 与 Myerson 等外部关系图不同（pp.1063–1064），提醒项目不要把数据库 schema 图当成语义依赖图。
4. **[基于原文推导]** R1/R3 应分别记录 provenance adjacency、coordinate overlap 与 semantic dependency；三者之间的差集本身可能揭示由 `G` 诱导或消除的交互。
5. **[基于原文推导]** R2 多 G 复用可先共享一张“依赖候选超图”，再为每个 `G` 剪枝；但剪枝正确性需要符号证书，不能靠采样联盟判断无依赖。
6. **[新研究设想]** 研究 SQL 查询类到 dependency graph 的静态上界：由 lineage 中的共现给出无漏边候选，再用聚合/价值函数代数化简删除假边；比较候选度与真实度。
7. **[新研究设想]** 定义“依赖发现—求解总成本”参数化管线：`T_total=T_candidate+T_certify+T_FPT`，并寻找在哪些完整报表查询类上证书可多项式生成。
8. **[新研究设想]** R5：数据更新只影响依赖图局部时，能否增量维护 `D(i)` 和局部边际表；先证明影响域，再谈动态加速。

业务证据要求：dependency 是游戏数学对象，不提供 `G` 的现实合理性。业务任务只能帮助冻结 `G`，不能替代语义依赖证明。
