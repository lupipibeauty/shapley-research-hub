# v3.2 到 v3.3 实验设计变更记录

状态：协议已修订，新增阶段尚未执行。

| 项目 | v3.2 | v3.3 |
|---|---|---|
| 现有方法角色 | 以适用性审计为主，B5 为接口占位 | 原目标复现、D1-P 等价适配和边界实验为必做主线 |
| 工作顺序 | 先 S0/S1，再考虑文献方法 | D1-P 精确真值轨道与官方算法复现轨道并行，在适配实验汇合 |
| 首批外部基线 | 未指定真实运行对象 | Abramovich Python 仓库和 Luo Rust 仓库优先 |
| 状态字段 | 适用性与少量运行状态混合 | 理论适用性与复现状态完全分离 |
| 失败解释 | 主要要求不把软件失败当理论结论 | 增加获取、安装、构建、接口、玩家、假设、错误输出、超时和内存分类 |
| 性能比较 | SQL-P/SQL-U/ST 为主 | 增加原算法逐查询、共享预处理、统一联盟价值三路径 |
| 边界结论 | 可由文献归约与最小反例推进 | 必须有真实复现、同目标准确性和最小案例证据 |
| 停止条件 | 首轮止于 S1 | 可信基线前不做百万级结论、不设计新算法 |

保持不变的部分：

- 主游戏仍为逻辑记录包玩家的标准记录级 Shapley；
- owner 第一轮仍只是支付汇总元数据，owner 联盟游戏另行定义；
- D1-P 使用现有 `p1..p12` 冻结数据和 35 坐标报表；
- V0、V-count、V1、V2 的定义与 v3.2 配置保持不变；
- 旧 D1 结果只作历史回归，不属于 v3.3 D1-P 结果；
- 所有结果和实验说明均使用中文。

新增证据仅确认两个官方仓库及其 README 入口存在，不表示本地部署或复现已完成。
