# H5-SCALE 算法正确性审计

日期：2026-11-01  
状态：通过；本轮暂停

## 1. 关卡与真值分层

1. `n<=18`：B0 枚举全部 `2^n` 联盟，直接从各记录增量计算价值和逐玩家 Shapley。
2. 通过 5,000 状态资源门槛的小规模配置：B2、B3、B4 分别独立计算并与 B0 逐玩家比较。
3. `n=100/1000` 完全共享线性控制组：B5 从每条记录的线性系数直接计算；B6 独立使用对称性 `1/n`。两者不使用已知 Shapley 支付构造输入。
4. 对未通过资源门槛的大规模非共享配置，不输出支付，不声称有精确真值。

## 2. 正确性结果

- `correctness_audit.csv` 共 48 条“实际运行方法 × 配置 × 评分”记录，全部通过 `1e-9` 容差。
- 最大逐玩家绝对误差为 `1.434269369937624e-14`。
- 最大效率性误差为 `2.292610545850949e-13`。
- 48 条失败/跳过记录中，42 条是 `SKIP_PREDICTED_STATE_CAP`，6 条是 `SKIP_N_GT_18`；没有正确性关卡失败、内存错误或运行时异常。
- `record_shapley_verified.csv` 只写入已通过关卡的支付。

## 3. 生成器和有效维度审计

`generator_effectiveness_audit.csv` 对 320 个“配置—实例—维度”单元检查了满表总量、实际影响玩家数和评分族使用情况。G1/G2 的每个增加维度都实际进入价值评价；G3 未被映射的原始维度是为了构造“同一原始记录、改变族间共享”的受控对照，不计为 G2 维度扩展。

## 4. 独立测试

`tests/test_h5_scale.py` 的 6 项测试全部通过，覆盖：

- 种子确定性；
- B0/B2/B3/B4 小游戏逐玩家一致；
- 可达状态不超过联盟数；
- 新属性具有真实价值作用；
- 完全共享时可加/几何游戏的代数坍缩；
- `n=100` 的 B5/B6 独立精确交叉验证。

## 5. 局限

- 5,000 状态是本轮 Python 实现的实验资源门槛，不是时间复杂度下界。
- B2/B3/B4 当前对玩家分别求边际，没有实现 Abramovich 式的一次反向求导；因此其实测时间是基线实现时间，不是该类经典方法的最优实现界。
- 大规模精确支付仅对“完全共享后坍缩为线性 P 族”的控制组成立，不是冻结四族 V2 的大规模真值。
