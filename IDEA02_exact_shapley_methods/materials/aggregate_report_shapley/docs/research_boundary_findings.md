# 研究边界与当前发现

## v4.0 证据门槛

现有算法的“计算边界”不能只由论文假设或接口说明推出。至少需要：原目标真实复现、同玩家同价值的 D1-P 适配、精确真值核验、端到端成本记录，以及异常的最小案例。安装失败、接口不匹配、理论假设不满足、超时和内存耗尽必须分别报告。在这些证据形成前，只能写“待检验”或“经验性失败”，不能写成现有算法的一般缺陷。

## 修订后的研究对象

研究对象是多源层次化汇总报表这一完整信息产品，而不是人口统计本身。人口统计只用于构造可理解的多来源、可空属性、层次节点和比例指标。v3.2 当前唯一玩家是逻辑记录包；owner 只作为付款汇总字段，owner 游戏属于后续独立扩展。

当前尚无 D1-P 实验结果。v4.0 优先执行 S0、S1、R0、R1：S1 建立 SQL-P、SQL-U、增量状态、价值性质和精确 Shapley 真值；R0 真实复现 Abramovich 与 Luo 官方算法；R1 在同玩家、同联盟数据库和同价值函数下适配。S2 组合实验和 S3 D1-X 等待这些结果。层次值、owner 游戏和 Jiang 适配不属于标准记录级直接性能基线。

## 由所附来源支持的边界

1. 一旦固定玩家单位、联盟数据库语义和整份报表价值 `v(S)`，记录级标准 Shapley 在定义上没有歧义；首要困难是计算。
2. Besner 的 Shapley 层次值要求嵌套的玩家划分；报表输出层次不会自动成为玩家层次。
3. Jiang 的无偏性陈述针对分片聚合排列空间上的 Ensemble Shapley，不能原样移植到 SQL 查询状态合并。
4. Livshits 等人研究单个数值查询的元组贡献；分组输出可拆成多个数值查询，但非线性整表价值仍需另建模型。
5. Luo 等人的加速依赖独立可加元组效用和所有者级最小合成；V2 有意不满足这一可加假设。
6. Standke–Kimelfeld 的边界适用于无自连接的单个聚合合取查询和局部值函数：求和/计数对应 ∃-层次，去重计数/最小值/最大值对应全层次，平均值/分位数对应 q-层次，“存在重复”对应强 q-层次。整份 V2 报表、多输出交叉层次、自连接和非局部价值不自动落入这些边界。

## 来源核对后仍未解决的问题

- SQL-U 的物化和 ST 的状态构造在计入准备成本后，是否仍比逐联盟 SQL-P 更低；
- V-count 闭式、B1 子集公式和 B4 独立审计能否逐记录一致；
- V1 的坐标/统计族分解能复用到什么程度，以及 V2 的交互从何处破坏分解；
- V1 是否出现负边际、负 Shapley 或非单调联盟；
- 简单一对一/可空连接的成本能否被普通增量统计完全解决；
- S2 组合实验是否仍留下不能由输出量、Python 循环或普通数据库实现解释的瓶颈；
- 各报表查询模板在 Standke–Kimelfeld 分类中的准确层次类别，以及整表非线性组合后的复杂度。

Abramovich 官方仓库及 README 已核验，确认其提供 LExaShap/LExaBan、SUM/COUNT 与 MAX/MIN 的来源表达接口和示例入口；但尚未本地部署、运行或适配，因此理论适用性仍为 `UNVERIFIED`，复现状态为 `NOT_STARTED`。目前不得写出其已支持完整 GROUP BY 报表、来源共享或批量计算的结论。

## 旧 D1 精确结果（历史基线）

以下是旧版 13 单元阈值博弈的精确结果，不是抽样估计，也不是 D1-P 的结果。

1. V1 下所有受限规则都不同于标准 Shapley；L1 距离均为 `40/3`，最大逐记录差为 `5/3`。
2. V2 下，城市连续规则相对标准 Shapley 的 L1 距离为 `196/33`；地区连续和 Shapley 层次值均为 `508/33`。这只是当前控制博弈的性质，不是一般支配结论。
3. D1 的 V1、V2 下，地区连续 A4 与地理 A5 恰好相同；两种方法一般并不等价，因此只能将其表述为特定数据和价值函数下的巧合。
4. 标准 V1 对小地区每条记录支付 `65/6`，对大地区每条支付 `85/12`；地理 A5 分别支付 `25/2` 和 `25/4`。A5 先把两个顶层地区各分 50，而标准 Shapley 没有这一约束。
5. A0、A4、A5 均通过各自独立精确核验，所以观察到的支付差异属于分配规则差异，不是数值或 SQL 错误。
