## 1. 保留的研究主线

研究对象继续为多源层次化汇总报表的记录级收益分配。多个来源提供底层事实记录，记录通过层级映射、类别关系、JOIN、GROUP BY 和逐级聚合进入多个汇总节点，形成包含总体、中间层和细分层统计的完整报表。报表作为一件信息产品取得收入 `R`，在固定联盟数据库、报表程序和整表价值函数后，计算逻辑记录包的标准 Shapley。

主游戏保持不变：

\[
B_i=\{Basic(i),OptionalAttribute(i)\},
\]

\[
D_S=D^{fixed}\cup\bigcup_{i\in S}B_i,
\qquad Y(S)=Q(D_S),
\qquad v(S)=G(Y(S)).
\]

- 玩家是逻辑记录包，不是 JOIN 后的物理行；
- 基本事实与同一 `record_id` 的可选属性一起激活；
- `OwnerMap` 只把记录支付汇总给收款 owner；
- owner 作为玩家属于另一场游戏；
- 报表节点层次 `H_report` 不是玩家层次；
- 第一轮不引入 Owen 值、Shapley levels 或其他层次分配规则；
- 人口统计只是完全合成、便于理解的首轮场景，不支持现实人口价值或社会公平结论。

### 2.2 D1-P 构造

D1-P 是完全合成控制数据：

- 四张基本来源表 `BasicSource_A1/A2/B1/B2`；
- 一张可缺失属性表 `OptionalAttribute`；
- 外生固定的 `Hierarchy`、`CategoryADim`、`CategoryBDim`；
- 仅用于付款汇总的 `OwnerMap`；
- 12 个逻辑记录玩家 `p1..p12`；
- 七个节点 `COUNTRY/A/B/A1/A2/B1/B2`；
- 每节点五个输出：记录数、E2 数、E2 占比、有属性数、制造业占有属性比例。

内部只维护 `total/E2/present/manufacturing` 四个可加计数，比例从分子分母派生。空节点保留：计数为 0，比例在 SQL 层为 `NULL`。

### 2.3 三个真值实现

- SQL-P：四张基本来源 `UNION ALL`，按联盟激活记录，连接固定维度和可选属性，展开到叶/父/根并补全七节点骨架；
- SQL-U：物化统一逻辑事实表后执行等价查询；
- ST：加入一个记录时只更新其三个祖先节点的四个基础计数。

全部 4096 个联盟必须逐节点、逐内部计数、逐输出坐标和逐 `NULL` 标志一致。

## 4. 阶段 S1：D1-P 精确真值与价值性质检查

状态：`NOT_RUN`。S1 与 R0 可以并行准备；R1 必须使用 S1 真值。

### 4.1 联盟与报表真值

1. 固定 `p1..p12` 位序，枚举 `mask=0..4095`；
2. 对每个联盟生成 SQL-P、SQL-U、ST 报表；
3. 对整数严格相等，对比例比较精确分子分母，不比较四舍五入显示值；
4. 对 `S={p1,p2,p3}` 执行冻结硬编码断言；
5. 保存联盟、四个内部计数、35 坐标、`NULL` 标志和三个实现哈希。

### 4.2 三类精确基准

- Oracle-1：SQL-P 联盟价值表 + Shapley 子集公式；
- Oracle-2：ST 共享统计状态 + 同一联盟/同一价值函数；
- Oracle-3：只对有等价证明的坐标得分游戏使用 Shapley 线性性分解。

Oracle-1 用 Möbius/Harsanyi 或另一独立实现交叉核验；3–6 玩家 toy case 可枚举全部排列。12 玩家不要求枚举 `12!` 排列。

### 4.3 V1/V2 性质检查

完整推导和数值规则见 `docs/value_property_audit.md`。执行时必须：

- 用有理数精确计算 V0、V-count、V1、V2(`λ=0`) 和精确 Shapley 权重；
- 用 80 位高精度计算 V2 几何项，边界边际用 120 位复核；
- 区分 SQL `NULL`、价值层得分 0 和满联盟参考值无效；
- 对每个价值函数遍历 `12×2^11=24576` 条可加入边；
- 输出负/零边际、最小/最大边际、值域、Shapley 最小值和预算误差；
- 精确断言 V2(`λ=0`)=V1；
- 若冻结 V1/V2 出现负边际，先检查动态归一化、NULL、JOIN 计数单位和坐标错位。

理论预审表明：在参考值固定、权重非负、坐标有效性不随联盟变化时，计数覆盖率和带覆盖率的比例得分单调，非负加权和与加权几何平均也单调。该推导不替代 4096 联盟程序检查。

### 4.4 S1 通过门槛

## 7. 后续 S2：完整 35 坐标组合实验

状态：`DESIGNED / NOT_RUN`。S2 等待 S0、S1、R0、R1 结果确定重点，不在本轮自动执行。

### 7.1 共同参照

所有组合实验从完整 D1-P 的七节点、35 坐标、逻辑记录玩家出发。消融只用于解释瓶颈；改变输出或价值函数时必须创建新的 `game_id`，支付差异不计算为算法误差。

### 7.2 三组核心组合

| 组合 | 构造方式 | 主要判断 |
|---|---|---|
| 层次×多指标 | 在根/父/叶同时保留计数与比例得分 | 重复来源编译、坐标合成和共享状态成本 |
| 多指标×JOIN | 固定七节点，引入可选属性或等价物化视图 | JOIN/见证成本与指标宽度是否交互 |
| 层次×复杂来源 | 固定指标族，增加跨层共享见证或重复路径 | 来源表达结构而非输出数是否主导成本 |

每组比较：适用的现有算法、Oracle-1 精确计算、Oracle-2 共享统计实现。预处理、查询/见证、来源构造、编译、价值评价、Shapley 求解和后处理分别计时。

### 7.3 二因素成本交互

固定其他条件，记录 `T00/T10/T01/T11`，计算：

\[
I=T_{11}-T_{10}-T_{01}+T_{00}.
\]

该值只描述被测实现的成本交互，不是复杂度下界。每个条件至少重复 5 次，报告中位数和 IQR；冷启动与预编译复用分开。

### 7.4 异常最小化

异常先压缩到 3–6 玩家，依次检查 SQL、玩家变量、价值函数、等价转换、代码接口和资源瓶颈。最小案例至少保留：SQL、数据、oracle、基线输出、环境、性能剖析和论文假设核对。
