# D1-X 复杂结构扩展规范 v4.0

状态：`DESIGNED / NOT_RUN`。D1-X 是 D1-P 之外的后续扩展族，不覆盖 `config/d1p_design.yaml`，也不属于本轮 S0/S1/R0/R1 的执行范围。

## 1. 共同原则

- 每个 D1-X 实例从冻结 D1-P 复制后增量构造；
- 每次只新增一种主结构，保留父版本和构造日志；
- 玩家仍为逻辑记录包，除非显式创建另一场游戏；
- 固定维度保持外生；跨来源受控元组若变成玩家，必须新建 GameSpec；
- 每个统计明确使用物理行数、见证数、`COUNT(DISTINCT record_id)` 或其他计数单位；
- 同时记录完整报表输出坐标数 `m_output` 与独立基础统计状态数 `m_state`；
- 所有扩展重新建立 SQL 真值、联盟价值和最小正确性样例。

## 2. 扩展阶梯

### X1：交叉分组

在七节点层次之外增加类别 A×类别 B 或层次×类别的交叉输出。构造时保存：

- 交叉维度定义及固定骨架；
- 输出坐标到基础计数状态的映射；
- 空交叉组的 `NULL` 规则；
- `m_output` 与可共享 `m_state`。

目标是区分“输出变宽”与“独立状态真正增加”。

### X2：多对多映射

允许一条逻辑记录映射到多个标签或类别。至少建立两个不同产品：

1. 标签出现次数产品：同一记录可贡献多次；
2. 唯一记录产品：使用 `COUNT(DISTINCT record_id)`，同一记录每组至多贡献一次。

二者查询和价值函数不同，支付差异不能解释为算法误差。

### X3：重复连接路径

增加可使同一逻辑记录通过多条见证到达同一输出的关系。必须记录：

- 每个输出事实的见证数；
- 集合语义与袋语义；
- 来源表达中的重复变量和共享子表达式；
- 是否发生自连接；
- 原算法是否支持同一玩家变量在多个位置绑定。

### X4：跨来源依赖

构造只有多个来源元组共同出现才能产生输出的关联。分两种游戏：

- X4-R：相关元组仍绑定到同一逻辑记录玩家；
- X4-S：不同来源所有者分别控制元组，需要新的多来源供给 GameSpec。

X4-S 不得继续沿用 D1-P R-game 名称或真值。

## 3. 每个扩展的必交付字段

| 字段 | 含义 |
|---|---|
| `parent_dataset` | 直接父版本 |
| `construction_script` | 可重复构造步骤 |
| `added_structure` | 本次唯一主变化 |
| `player_spec` | 玩家及变量绑定 |
| `counting_unit` | 每个统计的计数单位 |
| `m_output` | 完整报表坐标数 |
| `m_state` | 独立基础统计状态数 |
| `join_witnesses` | JOIN 见证及重复情况 |
| `game_id` | 查询、玩家、价值函数的联合版本 |
| `oracle_status` | 真值状态 |

## 4. 后续比较

对同一 `game_id` 比较精确计算、适用的已有算法和共享统计实现，分别报告：预处理、查询、见证/来源编译、价值评价、Shapley 求解、峰值内存以及 `m_output/m_state`。若成本主要由 `m_state` 而不是 `m_output` 决定，只能先作为经验观察；需要跨实例重复和最小案例后才能形成研究判断。
