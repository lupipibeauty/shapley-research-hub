# P3-0 后续层次报表充分性审计

## 当前判断

应先保持静态双组问题，不立即扩展多层报表。本轮证明经典 MTBDD/加权模型计数能精确解决 13 玩家锚点，却没有证明它在更高来源宽度下的增长界，也没有证明多层坐标提供新独立状态。

## 层次坐标的进入条件

1. 若每个实体只属于一个互斥叶地区，父级 `COUNT DISTINCT entity` 可由叶计数直接求和；这是确定性汇总，不是新联合状态。
2. 若同一实体可属于多个叶节点，叶计数可能不能决定父级 DISTINCT。后续必须先给出“旧叶状态相同、父级去重不同”的具体反例，并将 Membership/Activity 定义为清楚的可变事实玩家。
3. 只有父级统计无法从当前充分状态恢复、引入了新玩家依赖，或导致可共享来源必须重复编译时，才启动新的层次算法实验。

## 交叉维度与多指标

地理×类别叶单元已完整保存时，地理总计和类别总计通常只是确定性汇总。如果新交叉统计无法从旧状态恢复，必须用成对联盟/实例证明缺少的联合分布信息。

指标仅按 `COUNT DISTINCT → COUNT(*) → SUM → AVG → ratio` 逐一进入，每次明确统计单位、bag 重复、NULL、充分统计量和来源算法支持。AVG 可由 SUM/COUNT 恢复时不得当作独立新维度；ratio 必须保留分子与分母。新坐标若不参与 G 也不改变旧坐标，不能把 SQL 输出时间增长解释为 Shapley 更难。

## 下一轮唯一建议

若继续，优先做“固定 SQL/G/玩家定义，单独提高 JOIN 来源共享宽度”的小型结构扩展，并比较 MTBDD 节点数、变量顺序、条件计数重用和全玩家求解成本。在看到可复核的结构瓶颈前，不应同时加玩家、加层级和加指标。
