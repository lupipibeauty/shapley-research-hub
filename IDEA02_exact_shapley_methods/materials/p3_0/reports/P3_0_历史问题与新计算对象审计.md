# P3-0 历史问题与新计算对象审计

## 结论

本轮的固定对象不是普通 SQL 查询耗时，而是一个 13 条物理事实记录构成的合作游戏：Entity–Link–Attribute 的跨玩家 JOIN 证据先生成 A/B 两组 `COUNT DISTINCT entity_id`，整表效用再取 `G0=q_A+q_B` 或 `G1=min(q_A,q_B)`。最后依标准 Shapley 贡献比例分配外生收入池 `R=1000`。

它与历史工作的关系是“组件已被分别研究，本轮组合尚未原生求解”，不能说整个问题从未被涉及：

| 历史阶段 | 已验证部分 | 对当前对象的缺口 |
|---|---|---|
| D1-P/S0/S1 | 记录玩家、7 节点/35 坐标报表 | 没有当前三表跨玩家 DISTINCT 来源 |
| AB-J1/J2 | JOIN、DISTINCT、替代证据、HAVING | 没有两组联合 `MIN` 效用与全玩家联合分布 |
| AB-N4-DP | 低维计数状态 DP | 不编译当前 OR-of-AND JOIN 来源 |
| H3-CONTROL | 跨玩家 JOIN、DISTINCT/HAVING、因子基线 | 没有固定的 A/B DISTINCT + MIN 收入游戏 |
| H5/H5-R | 联合状态、生成函数、全玩家共享 | 输入是可加的记录增量，不是当前 JOIN 证据 |
| P2 | Q2 形状和精确 Shapley | `compile_state_transitions` 消费预先计算的全联盟报表，不是原生 DB-to-Shapley |

详细证据路径与状态见 `results/historical_overlap_audit.csv`。历史文件均只读，本轮未重跑已有实验，因此除 P3-0 自身外均标记为 `SOURCE_VERIFIED`，不冒充 `REPRODUCED`。

## 数据库与玩家语义

- 13 个玩家为 4 条 Entity、6 条 Link、3 条 Attribute 物理事实；JOIN 行不是新玩家。
- 满库主键、唯一性和 Link→Entity/Attribute 引用完整性由 SQL schema 强制。联盟库不物理删除违反外键的行，而是按玩家 mask 在查询中启用事实，JOIN 自然过滤不完整路径。
- 6 条 grounding 都是 3 个不同类型玩家的互补。E1/E3 各有两条替代路径，A1/A2/A3 均跨实体复用，其中 Attribute 还跨 A/B 组。
- 只改变 `source_id` 物理分区而不改变逻辑事实和玩家 ID 时，8192 个联盟的游戏全部不变。因此物理分区成本不应混入 Shapley 来源依赖。

## 现有理论与软件的边界

Kara、Olteanu 和 Suciu 给出了 Shapley 与模型计数的联系，并讨论 d-DNNF 上的计算；这支持本轮将每个实体资格看作 Boolean 来源后做计数，但两输出数值 `MIN` 仍需要联合终端状态适配，不是论文结论的无条件直接调用。Abramovich 等的 lineage lifting/梯度路线对 Boolean 输出有关，但也不应被宣称为任意联合整表效用的现成解。Livshits 和 Standke–Kimelfeld 的可处理性结论需逐项核对自由变量、聚合和局部价值假设，不能用查询图外观替代定理前提。

因此，本轮结论是：“经典模型计数/决策图的可执行适配”，而不是新算法或新复杂性定理。
