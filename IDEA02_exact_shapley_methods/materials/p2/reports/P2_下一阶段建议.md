# P2 下一阶段建议

## 明确判断

P2 没有发现足以立即开发新 Shapley 算法的静态结构缺口。当前低宽度来源、树形/交叉报表和联合效用可以由完整枚举与经典状态表示精确处理；观察到的主要成本是输出展开。

## 是否进入 P3

建议只进入一个受限的 **P3 强基线反证关卡**，而不是扩大随机实例或开发新算法：

1. 固定 Q2-NH、12–16 玩家、grounding 数、满联盟报表和完整 G2。
2. 构造联合来源—价值因子宽度 2、3、4 的输出匹配实例。
3. 原生实现或适配经典变量消去/加权模型计数。
4. 以 Abramovich/LExaShap 处理 Boolean 输出来源，明确整表 G2 的适配边界。
5. 与 H5 共享状态方法比较中间因子数、编译时间、全玩家求解和进程 RSS。

停止条件：如果经典变量消去或模型计数按宽度参数稳定处理，则静态联合报表算法方向停止；转向动态 Shapley 更新的独立文献审计。若无法实现强基线，只能标记 `ADAPTER_REQUIRED`，不能据此认定算法缺口。

## 不建议继续的方向

- 不再增加 F1/F2 的随机种子或单纯扩大 n。
- 不把 H2 SQL 时间上升解释成 Shapley 难度。
- 不把 G2 的非加性本身解释成状态爆炸。
- 不直接启动 Q3/Q4/Q5；只有宽度关卡需要时再选择最小查询。

P3 尚未启动。
