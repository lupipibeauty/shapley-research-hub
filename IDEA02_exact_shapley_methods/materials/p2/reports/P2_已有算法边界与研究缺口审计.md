# P2 已有算法边界与研究缺口审计

## 一、已经被现有方法覆盖的部分

1. G0、G1 可按坐标线性分解；本轮逐记录误差不超过 `3.65e-14`。
2. 纯 bag grounding 仍可使用逐 witness 分摊闭式；non-hierarchical 查询形状本身不构成本轮 G0 困难证据。
3. 小规模完整联盟、Möbius/Harsanyi 和充分状态转移均可精确计算。
4. 当前来源图的 min-fill 宽度上界均为 2，经典变量消去和模型计数在结构上是首要竞争方法。
5. Abramovich/LExaShap 可作为 Boolean 输出来源编译候选，但任意整表 G2 需要适配层；接口缺失不是理论缺口。
6. Livshits、Standke–Kimelfeld 的结果必须按查询输出、自由变量、事实玩家和局部价值假设分别应用；不能从 non-hierarchical 标签直接推出本游戏困难。
7. Luo 的独立效用假设只覆盖受限可加输出价值，不覆盖本轮完整 G2。

## 二、没有被本轮证实的候选困难

- 来源共享导致状态爆炸：未证实。匹配 high/low 只出现 6.5% 转移签名差异。
- 交叉报表导致新的状态维度：未证实。H2 状态数与 H1 相同。
- 联合效用导致求解状态增长：未证实。G2 交互增强，但复用相同报表状态。
- F×H×G 出现额外组合瓶颈：未证实。八组状态交互为零。

## 三、软件接口与未测量项

- LExaShap/d-tree 原生适配：`ADAPTER_REQUIRED`，不是性能失败。
- 原生变量消去/加权模型计数：`STRUCTURALLY_APPLICABLE_NOT_MEASURED`。
- H5 状态实现到 P2 JOIN 证据状态：`ADAPTER_REQUIRED`。
- DuckDB 原生峰值 RSS：`NOT_MEASURED`；当前 CSV 仅含 Python 跟踪内存。
- Q0/Q1 已在 P1 全联盟核验，本轮未重复运行；Q1/Q2 业务谓词不同，只作查询类别对照。

## 四、结构缺口矩阵判断

唯一仍值得做最小 P3 反证的是：固定 Q2、玩家数、grounding 数、满联盟输出和 G2 语义，构造联合因子宽度 2/3/4 的阶梯，然后比较原生变量消去、加权模型计数与来源编译。

这不是算法创新命题。只有强基线在匹配实例上显示可重复的中间因子增长，而且该增长不能由输出宽度或接口适配解释时，才可能保留为后续算法问题。

当前证据不支持继续扩大 F1/F2 星形或路径实例，也不支持把 H2 的 SQL 变慢包装成 Shapley 创新。

## 五、证据等级

- 实际验证：全部 CSV 数值、SQL/oracle 一致性、双 Shapley 误差、八组筛查。
- 数学推断：线性分解、效率性、状态转移复用。
- 文献映射：现有 CQ、来源编译、变量消去和独立效用适用条件。
- 待验证假设：联合宽度增长是否在输出匹配后仍形成原生精确计算瓶颈。
