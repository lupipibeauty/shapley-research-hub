# Luo（2024）复现失败原因与可执行操作

更新日期：2026-11-06  
证据范围：`BRBD_v1` 本轮真实编译、数据生成、assignment 与 TPC-H 运行日志。

## 结论先行

Luo 官方核心程序已经成功以 Rust 1.75 release 配置编译；TPC-H SF=0.1 的 RDSV 已端到端运行成功。TPC-H SF=1 的失败发生在 8 表 JOIN 阶段，属于本机内存不足，不是算法输出错误，也不是输入 schema 错误。

## 一、正式尺度 SF=1 为什么失败

实际执行到以下阶段：

1. 8 张 TPC-H 表与 16 个 owner assignment 文件均成功读取。
2. 数据装载耗时 37.9369674 秒。
3. 程序进入 `game::join`。
4. 申请额外 570,425,344 字节时失败，Windows 退出码为 3221226505。
5. 没有生成 Shapley JSON，因此不得声称 SF=1 已复现成功。

论文实验机器为 Ubuntu 20.04、125GB RAM；当前机器约 14GB RAM。最直接的正式复现办法是：

```text
环境：Ubuntu 20.04（或内存行为可控的 WSL2）
内存：建议接近论文的 125GB；至少应显著高于当前 14GB
Rust：1.75.0
源码 commit：2a514fb4a0e3d45365d6dffe6435f93499afd7e3
编译：cargo build --release --bin cal_sv --locked -j 1
运行：cal_sv -d tpch -c <SF1 CSV> -a <assignment> -o rdsv.json -m rdsv -t 1
```

若只增加 Windows pagefile，可能让 JOIN 通过，但会引入大量换页并扭曲运行时间；此方案可用于正确性排障，不宜与论文时间直接比较。

## 二、为什么最初无法编译

### 1. 新版 Rust 不兼容旧依赖

Rust 1.99.1 编译 `ethnum 1.3.0` 时出现 E0512；这属于旧锁文件与新编译器的兼容问题。改用历史复现记录一致的 Rust 1.75.0 后消失。

### 2. GNU 工具链不能稳定处理中文真实路径

即便使用 Windows 短路径或 `subst`，Cargo/Rust 仍会把部分依赖路径规范化为包含“python项目”的真实路径，GNU linker 随后报告文件不存在。解决办法是同时把 Rust 工具链和临时源码构建副本放到真正的纯 ASCII 路径。本轮使用：

- `D:\BRBD_rustup`
- `D:\BRBD_cargo`
- `D:\BRBD_build_src\official_checkout`

工作区内官方检出保持未修改，成功二进制与哈希回存 `BRBD_v1`。

### 3. 同时编译两个 LTO 二进制导致 OOM

作者 `Cargo.toml` 固定 `lto=true`、`opt-level=3`、`debug=true`。`cargo build --release --bins` 会同时进行两个重型 LTO，实际触发 `LLVM ERROR: out of memory`。串行编译解决：

```text
cargo build --release --bin cal_sv --locked -j 1
cargo build --release --bin cal_sv_ablation --locked -j 1
```

已成功生成的 `cal_sv`：415,734,184 字节，SHA-256 为 `F4C57C2160C0CE325832E5DEDD182902C6C8603B060747CDB96C44FBD501B1D6`。

## 三、assignment 脚本为什么失败

仓库没有声明 Python Polars 版本。作者代码执行：

```python
groupby("owner").agg(pl.count("owner"))
```

之后却读取 `owner_count`。实际在 Polars 0.13.62、0.15.18 和 0.19.19 均产生重复列名错误。另一个问题是内部函数读取模块全局 `beta`；直接 CLI 恰好创建该变量，模块调用则报 `NameError`。

本轮没有修改官方文件，而是在独立 adapter 中：

1. 仅替换不影响输出的 owner 数量打印函数。
2. 显式设置与 CLI 参数相同的全局 `beta`。
3. 分配公式、随机抽样与 JSON 序列化继续调用作者函数。

需要注意：官方生成器没有 seed 参数，因此相同命令不能保证字节级重复。本轮通过输出 SHA-256 冻结实际 assignment。

## 四、缩小验证不等于正式复现

SF=0.1 是为区分“程序/输入错误”和“正式规模资源失败”而建立的兼容实验。它使用相同 8 表连接、500 owner、alpha=3、beta=3、max-copy=4 和同一 RDSV 程序，但数据规模缩小，且行数通过 adapter 注入作者 assignment 逻辑。

因此其证据标签为 `OUR_ADAPTER_OBSERVED`，不能替代论文 SF=1 结果。

完整机器可读失败清单见 `audit/luo2024_failure_ledger.csv`。
