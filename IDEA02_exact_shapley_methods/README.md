# IDEA02：精确 Shapley 方法与语义边界

## 1. 研究问题

在固定玩家、查询和价值函数下，不同精确算法、结构表示和作者实现是否计算同一个 Shapley 对象？哪些差异来自算法，哪些来自查询语义、玩家绑定或输入接口？

## 2. 探索路线与实验目的

### 旧 D1 与 D1-P

核验子集、增量状态、Harsanyi、排列等精确实现的一致性，并形成固定记录玩家下的回归基线。旧 D1 报告称正确性关卡通过，但原始 manifest、命令和逐项计时不完整；D1-P 后续成为更清晰的冻结模型线。

### P2 结构与价值实验

分别考察来源、层次、价值和查询因素，避免把所有差异归结为算法。现有材料位于 `projects/aggregate_report_shapley_structure_v12/P2/` 及相关实验目录。

### P3 子任务

- **P3-1B**：阈值准备与 8192 联盟 oracle 后验核验，准备完成并暂停。
- **P3-1C R1**：作者 LExaShap 小型 Boolean DNF 最小复现。
- **P3-1C R2**：P3-0 JOIN witness 转换的 H1/H2 DNF 同目标适配，与本地 MTBDD 对照。
- **P3-1C C2**：最小 SQL 语义控制；DuckDB 成功，ProvSQL 环境阻塞。

四项是不同任务，不是连续参数版本。

### LexaShap 与 M3

LexaShap 正式批次 7,864 行中 7,773 PASS、91 FAILED；91 项由 90 个 Python 整数位数限制和 1 个空 divisor 参数错误构成，尚未全部修复。M3 是 D1-P 设计修订，仍为仅设计；P3 MTBDD 不能回填为 M3 结果。
